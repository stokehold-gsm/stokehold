# Лицензии: эксплуатация

Для владельца и для помощников по выдаче. Архитектура и модель угроз: `docs/security-licensing.md`, решения: ADR 0001, 0003, 0004.

## Что где живёт
| Что | Где | Секретность |
|---|---|---|
| **Корневой приватный ключ** | офлайн у владельца, две копии | высшая. Потеря или утечка требует нового установщика и нового выпуска панели |
| Корневой публичный ключ | `internal/entitlement/roots/<id>.pem` (в git, вшит в панель) | публичный |
| **Онлайн-ключ + сертификат** (`online.json`) | `/etc/stokehold-license/online.json` на сервере, права 0600 | высокая; утечка ограничена сроком сертификата (90 дней) и отзывом по `kid` |
| База лицензий | `/var/lib/stokehold-license/licenses.db` | содержит хеши ключей, контакты |
| Лицензионные ключи покупателей | нигде не хранятся | показываются один раз при выдаче |

## Первый запуск (один раз)
На **своей** машине, без сервера:
```
go run ./cmd/stokehold-sign keygen root.key root1.pem
go run ./cmd/stokehold-license online-key -root root.key -root-id root1 -kid online-2026-11 -days 90 -out online.json
```
Положить `root1.pem` в `internal/entitlement/roots/`, выпустить новую панель. `online.json` скопировать на сервер (0600). Корневой ключ `root.key` убрать офлайн.

На сервере: установить бинарник `stokehold-license`, `deploy/stokehold-license.service`, `deploy/Caddyfile.license` (подставить свой IP в `remote_ip`), создать пользователя `stokehold-license`, затем создать владельца:
```
sudo -u stokehold-license stokehold-license admin-add -db /var/lib/stokehold-license/licenses.db -name owner -role owner
```
Команда печатает одноразовый пароль. При первом входе система заставит включить двухфакторную защиту, без неё остальные страницы закрыты.

## Ротация онлайн-ключа (каждые 90 дней, до окончания сертификата)
1. На машине с корневым ключом выпустить новый `online.json` с новым `-kid`.
2. Скопировать на сервер, `systemctl restart stokehold-license`.
3. Токены, выданные старым ключом, остаются действительными (сертификат проверяется на момент выдачи токена) до их срока; панели получают новые токены при суточном продлении.
4. Если онлайн-ключ утёк: сделать то же самое сразу и добавить старый `kid` в список отозванных (список отозванных в панели ещё не реализован, пока лечится выпуском новой версии панели с запретом этого `kid`).

## Процесс выдачи (ручной, пока нет автоматизации)
1. Покупатель оплачивает на Boosty или FunPay. Появляется заказ с номером.
2. Помощник или владелец **сверяет, что заказ оплачен и это именно этот тариф**.
3. На `admin.stokehold.online` → «Выдать»: номер заказа, число серверов, срок, контакт покупателя.
4. Ключ показывается один раз. Отправить покупателю в личные сообщения площадки. Не в публичные каналы.
5. Владелец формирует чек в «Мой налог» (помощники к платежам и чекам не допускаются).

Правила: один заказ даёт один ключ (система не даст выдать второй). Помощник выдаёт не больше 20 лицензий за 24 часа, владелец без ограничения. Отозвать, продлить, сбросить привязку может только владелец.

## Помощники (роль issuer)
- Создаёт владелец: `admin-add -name ИМЯ -role issuer`, пароль передаёт лично.
- Помощник видит список лицензий, контакты и номера заказов, не видит платежей (их в системе нет) и не может отзывать.
- Потерял телефон: `admin-reset-2fa -name ИМЯ`, он заново настроит 2FA.
- Увольнение: сменить ему пароль нельзя из интерфейса, поэтому пока удаляется через базу, или проще: `admin-reset-2fa` и не сообщать новый пароль. **Нужно добавить команду `admin-disable`** (в плане).
- Помощник подписывает обязательство о неразглашении, см. `legal/privacy.md`, раздел 7.

## Отзыв, продление, перенос
- Отозвать: интерфейс → «отозвать» (или `stokehold-license revoke -order ЗАКАЗ`). Работает при следующем суточном продлении панели, максимум через 7 дней.
- Продлить: «+30 дн.» (или `extend -order ЗАКАЗ -days N`).
- Перенос на другой экземпляр: «сбросить привязку», затем покупатель вводит ключ на новой панели.

## Журнал
`/audit` (владелец) и `stokehold-license audit`. Журнал связан цепочкой хешей: правка или удаление записи ломает цепочку, и страница это показывает. Проверять раз в неделю.

## Резервные копии
Раз в сутки `sqlite3 /var/lib/stokehold-license/licenses.db ".backup /var/backups/licenses-$(date +%F).db"` и копия на другую машину. Без базы все выданные ключи станут недействительными (хеш потерян). Хранить копии в зашифрованном виде.

## Логи и IP-адреса
Запросы к API видят IP-адрес. Хранить не дольше 30 дней (политика ПД). Настройка: ограничить срок журнала systemd (`journald.conf`, `MaxRetentionSec=30day`) и логи Caddy. **Пока не сделано**, пункт в `legal/privacy.md`, раздел 9.

## Мониторинг
`curl -s https://api.stokehold.online/v1/health` отвечает `ok`. Сертификат онлайн-ключа живёт 90 дней: сервер при запуске отказывается стартовать с просроченным, поставьте напоминание за 2 недели.
