# Если что-то не работает

Сначала смотрите журнал: `journalctl -u stokehold -u stokehold-helper -e`.

## Панель не открывается
- `curl -s http://127.0.0.1:8080/health` на самой машине должен ответить `ok`. Нет ответа: `systemctl status stokehold`.
- Снаружи панель недоступна по замыслу: она слушает только `127.0.0.1`. Нужен обратный прокси с HTTPS (см. install.md).
- Вход не проходит, хотя пароль верный, и страница открыта **по HTTP**: cookie помечены Secure и браузер их не отправляет. Откройте по HTTPS или уберите `-secure` в `/etc/stokehold/stokehold.env` (только для локальной проверки).
- После нескольких неверных паролей учётная запись блокируется на 15 минут, адрес ограничивается по частоте попыток.

## Забыл код настройки
Он печатается при запуске, пока нет ни одного пользователя: `journalctl -u stokehold | grep "setup code"`. Перезапуск службы выдаёт новый код.

## «Служебный процесс недоступен»
- `systemctl status stokehold-helper`. Сокет: `ls -l /run/stokehold/helper.sock`, владелец должен быть `stokehold`, права `srw-------`.
- Журнал helper показывает каждую операцию: пользователь, действие, результат. Запрещённые запросы видны как `ok=false`.

## «Не удалось найти серверы этого пользователя»
- Пользователь не внесён в `/etc/stokehold/adopt.conf` (одно имя на строку, без пробелов, не `root`).
- У пользователя нет `lgsm/config-lgsm/<имя>server`, то есть LinuxGSM там не установлен.
- Для аккаунтов, созданных helper, имя должно начинаться с `gs_`.

## Команда завершилась с ошибкой
Результат команды показан на странице. Типичные причины в LinuxGSM:
- не хватает зависимостей (`Missing dependencies: ...`): поставьте пакеты, которые он назвал;
- сервер уже запущен или остановлен;
- `stop` не успел остановить игру и она была завершена принудительно;
- LinuxGSM при каждом запуске скачивает свои модули с GitHub: без доступа к GitHub команды зависают или падают.

## Бэкап «остановил» сервер
Это поведение LinuxGSM: `backup` останавливает сервер, делает копию и запускает снова. Планируйте во время, когда игроков нет.

## Обновление не удалось
Установщик откатывается сам и печатает, что прежняя версия снова работает. Причину смотрите в `journalctl -u stokehold`. Повторите установку позже или с `--version` предыдущего выпуска.

## Сообщить о проблеме
GitHub Issues с версией панели (`stokehold version`), ОС, игрой и логом **без паролей, токенов и ключей лицензий**. Либо канал «баги» в Discord.
