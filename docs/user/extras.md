# Мониторинг, API, несколько машин, моды и Discord

Мониторинг открыт всем. Остальное на этой странице (API, машины, моды, вебхук Discord, публичная страница состояния, команды Discord к панели) входит только в сборку Pro: её код закрыт (ADR 0007), а включает функции лицензия. В Free-сборке этих страниц нет. Игровые серверы от этого не зависят.

## Мониторинг
Страница «Мониторинг»: процессор, память, диск, нагрузка за минуту и состояние каждого сервера. Раз в минуту панель снимает замер и спрашивает у LinuxGSM `details`. В памяти хранятся последние 60 замеров, после перезапуска панели график начинается заново. Число игроков видно, только если LinuxGSM его печатает для этой игры; если нет, в таблице стоит прочерк.

Работает на Linux, потому что читает `/proc`.

## Ключи API
«Ключи API» → создать ключ. Он показывается один раз и хранится в базе только в виде хеша. Ключ действует с ролью того, кто его создал: у наблюдателя только чтение, у владельца и админа ещё и управление.

```
curl -H "Authorization: Bearer shapi_..." https://panel.example.com/api/v1/servers
curl -X POST -H "Authorization: Bearer shapi_..." https://panel.example.com/api/v1/servers/3/restart
curl -H "Authorization: Bearer shapi_..." https://panel.example.com/api/v1/metrics
```

| Запрос | Что делает |
|---|---|
| `GET /api/v1/servers` | список серверов, состояние, игроки, машина |
| `GET /api/v1/servers/{id}` | один сервер |
| `POST /api/v1/servers/{id}/{действие}` | `details`, `start`, `stop`, `restart`, `backup`, `check-update` |
| `GET /api/v1/metrics` | последний замер машины |

Каждое действие пишется в журнал под именем владельца ключа. После пяти неверных ключей с одного адреса за минуту включается ограничение.

## Несколько машин
На второй машине поставьте агента:

```
sudo bash install.sh --agent
journalctl -u stokehold-agent -n 5
```

Агент принимает запросы панели по HTTPS на порту 9443 (откройте его только для адреса панели). При первом запуске он делает самоподписанный сертификат и печатает его отпечаток, секрет лежит в `/var/lib/stokehold-agent/secret`. Для существующих аккаунтов LinuxGSM на этой машине создайте `/etc/stokehold/adopt.conf`, как и на главной.

В панели: «Машины» → добавить, ввести адрес, отпечаток и секрет. Панель сверяет отпечаток при каждом соединении, поэтому центр сертификации не нужен. Дальше при установке и добавлении сервера появляется выбор машины. Расписания, редактор конфигов и состояние работают для серверов на любой машине. Машину с серверами удалить нельзя.

Что пока не умеет: переносить сервер между машинами и показывать нагрузку второй машины (мониторинг показывает только главную).

## Моды Factorio
У сервера Factorio в списке есть ссылка «Моды». Она читает `serverfiles/mods/mod-list.json` и включает или выключает моды, остальные поля файла (например, версию) не трогает. Сами файлы модов кладёте вы. Скачивание с портала модов панель не делает: порталу нужен ваш логин и токен, и я не хотел хранить их в панели. Для других игр страница так и скажет.

## Discord
Вебхук: «Интеграции» → адрес вебхука. Панель пишет туда, когда сервер запустился или остановился. Принимаются только адреса `discord.com/api/webhooks/…`.

Команды `/servers`, `/server`, `/metrics` дают собственный бот сообщества. Создайте приложение в Developer Portal, ключ API на панели и запустите `stokehold-bot` с переменными:

```
DISCORD_BOT_TOKEN=...  DISCORD_PUBLIC_KEY=...  DISCORD_APP_ID=...
STOKEHOLD_PANEL_URL=https://panel.example.com
STOKEHOLD_PANEL_TOKEN=shapi_...
STOKEHOLD_CONTROL_ROLE="Server Admin"
```

Зарегистрировать команды: `discord-setup -guild ID -register-panel-commands APP_ID`. `/servers` может вызвать любой участник сервера, `/server` и `/metrics` только участники с ролью из `STOKEHOLD_CONTROL_ROLE`. Бот видит панель только через ключ API, пароли ему не нужны.

## Публичная страница
«Интеграции» → «Публичная страница состояния». Без входа по адресу `/status` видны названия серверов и состояние, больше ничего.
