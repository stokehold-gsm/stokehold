# Находки прототипов (тестовый сервер, 2026-10-31)

Стенд: Ubuntu 22.04.5, 8 vCPU, 31 ГБ RAM, LinuxGSM v26.4.0, игра mcserver (Minecraft Java). Другие процессы на машине (пользователь factorio) не трогались, PID процессов до и после совпали.

## Что подтвердилось
- `./linuxgsm.sh mcserver` + `./mcserver auto-install` работают без интерактива под обычным пользователем без sudo.
- `start`, `stop`, `details`, `monitor`, `check-update`, `backup` отрабатывают, вывод читаемый (с ANSI-кодами, их надо вычищать).
- `check-update` отдаёт «Local build / Remote build / Branch», этого достаточно для UI «доступно обновление».
- Тесты `safefs` и `license` проходят на Linux, включая символические ссылки наружу (на Windows они могли пропускаться).
- Go-тесты кросс-компилируются на Windows (`GOOS=linux go test -c`) и запускаются на стенде, отдельная установка Go на Linux не нужна.

## Что влияет на архитектуру
1. **`auto-install` не ставит зависимости.** `start` падает с «Missing dependencies: openjdk-25-jre» и подсказкой `sudo apt install`. Значит, helper (root) сам разбирает этот вывод или список из `serverlist`/`detect-deps` и ставит пакеты. Список пакетов только из белого списка, а не из вывода как есть.
2. **Домашний каталог пользователя через `adduser` получается `0750`.** Helper обязан выставлять `0700` явно.
3. **`backup` останавливает и снова запускает сервер** (при настройках по умолчанию для mcserver). UI и расписание должны предупреждать об этом, а не считать бэкап «бесшовным».
4. **Остановка может не быть graceful:** сразу после перезапуска `stop` за 30 секунд не дошёл, LinuxGSM убил процесс. Панель не должна делать stop-start подряд без ожидания готовности (по `monitor`/query).
5. **Статистика LinuxGSM** при `auto-install` выключена, это хорошо. Но LinuxGSM при каждом запуске скачивает свои модули с GitHub (`fetching GitHub ...`), то есть **зависит от доступности GitHub**. Для российских пользователей это риск: нужен режим с зеркалом или предупреждение в доках. Открытый вопрос.
6. **Версия Java сменилась** (для mcserver теперь `openjdk-25-jre`): список зависимостей меняется со временем, нельзя зашивать пакеты в наш код.
7. sudo на стенде спрашивает пароль, поэтому helper как systemd-сервис от root (план из architecture.md) остаётся правильным решением, а не sudoers для панели.

## Открытые вопросы после прототипа
- Как закрепить версию игры (для mcserver `check-update` показывает ветку `release`, закрепление билда не проверено).
- Что делает `adopt` при чужих правках LinuxGSM-скриптов (нужен отдельный тест на уже существующем сервере, например на Factorio владельца в режиме только чтения).
- Запуск и поведение под systemd вместо tmux-сессии из сессии SSH (helper будет запускать от root без интерактивного входа, нужно проверить, что tmux в таком случае работает).

## Helper и lgsm (проверено на стенде)
- `internal/lgsm`: `Discover` нашёл реальный `mcserver` в `/home/lgsmtest`, статус читается из `details` (STOPPED). Тест `Discover` пропускается на Windows: там нет бита исполнения, тесты запускаем на Linux.
- `internal/helper` (root, unix-сокет): полный цикл create-user, install, start, details, stop прошёл через сокет. Журнал фиксирует uid, операцию и пользователя.
- Отклоняются: пользователь без префикса `gs_` (в том числе `factorio` и `root`), команды вне белого списка (`console`, `install` через `run`), другой Linux-пользователь не может даже подключиться (сокет принадлежит панельному uid, права `0600`, плюс проверка SO_PEERCRED).
- Повторный `create-user` существующего пользователя падает и не меняет его, `chmod` после неудачного `useradd` не выполняется (тест).
- Ошибка, найденная в процессе: сокет root с правами `0660` недоступен панели. Исправлено владельцем сокета.
- Пробел закрыт (2026-10-31): пакеты для `deps` теперь проверяются по белому списку из встроенных снимков `lgsm/data/*.csv` LinuxGSM (internal/helper/deps), а не только по форме имени. Снимки обновлять с каждым релизом.
