# Выпуск релиза и подпись

Установщик и обновления доверяют только файлам, подписанным ключом владельца. CI собирает файлы и создаёт **черновик** релиза, подписывает владелец у себя. Приватный ключ не попадает в git, CI и чат.

## Один раз: ключ подписи
```
go run ./cmd/stokehold-sign keygen release.key release.pub
```
- `release.key` (приватный) хранить на зашифрованном носителе, две копии в разных местах. Потеря ключа значит, что нужен новый релиз установщика с новым ключом, утечка значит, что кто угодно может выпустить «официальное» обновление.
- Содержимое `release.pub` вставить в `install/install.sh` вместо `REPLACE_WITH_RELEASE_PUBLIC_KEY` (между строками `PEM`). Пока заглушка на месте, установщик отказывается работать без `--pubkey`.
- Те же ключи потом используются для проверки обновлений внутри панели (фаза автообновлений) и могут быть разделены с ключом лицензий, но лучше хранить отдельные.

## Каждый релиз
1. `git tag v0.1.0 && git push origin v0.1.0`. Workflow `release` прогонит тесты, соберёт `dist/` (две архитектуры, установщик, `SHA256SUMS`) и создаст черновик релиза. Теги с дефисом (`v0.1.0-beta.1`) помечаются как pre-release, они идут в канал beta.
2. Скачать `SHA256SUMS` из черновика и подписать:
   ```
   go run ./cmd/stokehold-sign sign release.key SHA256SUMS SHA256SUMS.sig
   ```
3. Загрузить подпись: `gh release upload v0.1.0 SHA256SUMS.sig`.
4. Проверить на чистой машине: `sudo bash install.sh --version v0.1.0`, затем опубликовать черновик.
5. Положить `install.sh` на `dl.stokehold.online` (отдельный шаг, DNS должен работать).

## Что проверяет установщик
1. Подпись `SHA256SUMS` (OpenSSL 3, ed25519).
2. SHA-256 обоих бинарников по этому файлу.
3. Только после этого что-либо ставится. Любая ошибка прекращает работу, ничего не меняя.
4. При обновлении старые бинарники копируются в `/usr/local/lib/stokehold/previous`. Если новая версия не ответила на `/health` за 20 секунд, возвращаются старые, сервисы перезапускаются.

Проверено на Ubuntu 22.04 (тестовый стенд): подменённый бинарник и чужой ключ отклоняются до установки, обычная установка и удаление работают, обновление на неработающую подписанную версию откатывается.

## Каналы
- `stable`: последний обычный релиз (`/releases/latest`).
- `beta`: самый свежий релиз, включая pre-release.
- Критичные уведомления (уязвимость, сломанный релиз) дублируются в GitHub Releases и в панели.

## Известные ограничения
- Установщик ставит только на Linux с systemd, OpenSSL 3, архитектуры amd64 и arm64.
- Автообновление изнутри панели ещё не сделано (пока обновление: повторный запуск `install.sh`).
- Ключ подписи один. Ротация ключа потребует нового установщика, процедура не отработана.
