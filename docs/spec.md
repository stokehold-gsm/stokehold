# Спецификация продукта

Рабочее название: **Stokehold** (см. раздел «Название»). Статус: черновик фазы 2, ждёт «ок».

## Кому и зачем
Админ одного-нескольких игровых серверов (5-50 игроков) на своём VPS или железке. Сейчас он живёт в SSH и LinuxGSM. Хочет браузер, расписание, бэкапы и откат, и чтобы не надо было ставить Pterodactyl. Мелкие хостинги в MVP не целевая аудитория.

Позиционирование (рабочая гипотеза, проверить спросом): «панель поверх LinuxGSM, которая подхватывает серверы, уже стоящие у тебя, и ставится одной командой». AMP из России не купить (см. market.md), Pterodactyl/Pelican избыточны для одного VPS.

## Killer-фичи (что отличает)
Оценка каждой: польза, риск, честный предел.

1. **Adopt: подхват уже установленных серверов LinuxGSM.** Панель находит `*server` скрипты в домашних каталогах, читает конфиги и показывает их, ничего не переустанавливая и не перезаписывая. Польза: ноль миграции для таких, как я. Риск: разные версии LinuxGSM и самописные правки. Предел: чужие кастомные скрипты читаем только в режиме «управлять командами», конфиги не переписываем.
2. **Откат при обновлении.** Перед каждым `update` делается снимок (бэкап файлов игры и данных), при проблеме откат одной кнопкой. Польза: главная боль админа. Предел: **закрепление точной версии** возможно не везде. Для Steam-игр можно выбирать ветку (beta-branch) через SteamCMD, точная сборка по buildid требует прототипа, **не проверено**. В MVP: «отключить автообновление + откат из снимка», закрепление ветки там, где LinuxGSM/SteamCMD это позволяют.
3. **Бэкапы и вайпы по расписанию, бэкапы в S3.** Расписание, хранение N копий, выгрузка в S3-совместимое хранилище, проверка успешности. Вайпы через `rustserver full-wipe/map-wipe` для Rust и общий механизм «остановить, удалить указанные пути, запустить» для остальных.
4. **Discord как пульт.** Вебхуки в канал (старт, падение, обновление, бэкап) и бот с командами `/server start|stop|status`. Работа без Discord не нарушается: всё то же есть в панели.
5. **Публичная страница статуса** для игроков: онлайн, адрес, версия, без доступа к панели.
6. **Не зависит от внешних сервисов:** панель, лицензия и обновления работают и при недоступном Discord/GitHub (грейс-период, см. ниже).

Под вопросом (оценить после MVP): менеджер модов (Factorio mod portal), мониторинг ресурсов, REST API (в MVP только как внутренний, публичный во второй версии).

## MVP (v0.1-v0.3)
- Установка одной командой на Ubuntu/Debian (подписанный скрипт и бинарник), деинсталлятор.
- Одна нода (локальная машина). Мультиузлы не в MVP.
- Список серверов: установка нового из каталога LinuxGSM, adopt существующего.
- Старт / стоп / рестарт / статус / консоль в реальном времени (поток вывода tmux).
- Редактор конфигов с ограничением на разрешённые файлы сервера.
- Бэкапы (локально + S3), расписание, обновление с автоснимком и откатом.
- Пользователи, роли (owner / admin / viewer), 2FA TOTP, журнал действий.
- Discord-вебхуки; публичная страница статуса.
- Русский и английский интерфейс.
- Лицензионный ключ: проверка подписи офлайн, грейс-период (фаза 4).

Вторая версия: бот Discord с командами, менеджер модов, мониторинг, REST API, расписание вайпов с GUI, мультиноды, Hosting-тариф.

| Серверов | 1 | до 10 | позже |
| Старт/стоп/консоль/конфиги, adopt | да | да | |
| Локальные бэкапы, расписание | да | да | |
| S3-бэкапы, откат обновлений | нет | да | |
| Discord-вебхуки / бот, страница статуса | вебхуки | всё | |
| Роли для нескольких админов | нет | да | |

Цену определим после опроса сообщества (см. market.md, раздел цен). Принцип: свободное ядро, платное то, что нужно сообществам (S3, откат, роли). Остановка лицензии никогда не ломает уже запущенные игровые серверы и не блокирует уже настроенные бэкапы и запуск: теряются только Pro-действия (новые S3-задачи, новые админы).

Выдача: вручную через Boosty и FunPay (ADR 0001). Сотрудники магазина (ADR 0003) проверяют данные и выдают ключ из админки, без доступа к деньгам и отзыву.
