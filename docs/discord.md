# Discord-сервер проекта

Единственная площадка сообщества (решение владельца). Панель, лицензии и обновления от Discord не зависят; критичные уведомления дублируются в панели и в GitHub Releases.

Сервер «Stokehold GSM», guild id в CLAUDE.md. Раскладка в `internal/discordsetup/plan.go`, тексты в `texts.go`.

## Структура
Основной язык русский, английский вынесен в отдельную категорию. Языковых префиксов в названиях нет.

| Категория | Каналы | Доступ |
|---|---|---|
| 📌 ИНФОРМАЦИЯ | приветствие, правила, роли, новости, релизы, faq, планы | читать всем, писать модераторам и боту |
| 💬 СООБЩЕСТВО | общение, игры, серверы-участников | всем |
| 🛠 ПОДДЕРЖКА | помощь, баги, идеи, гайды | всем |
| 🌍 ENGLISH | start-here (приветствие, правила, FAQ), chat, help, bugs, ideas, guides | start-here только чтение |
| ⭐ ПОДДЕРЖАВШИЕ | бета-тест (Beta tester), pro-зал (Pro, Hosting) | по ролям |
| 🔊 ГОЛОСОВЫЕ | Общий, Помощь голосом, Играем | всем |
| 🛡 ПЕРСОНАЛ | модераторы, журнал, бот | только Moderator |

Оформление: названия вида `💬・общение`, заголовки категорий с эмодзи, закреплённые сообщения в виде цветных карточек (embed) со ссылками на каналы.

## Роли
Персонал и тарифы (выдаёт владелец или бот по лицензии, кнопкой не берутся): Founder, Moderator, Hosting, Pro, Beta tester, Free.
Самовыдача кнопками в `🎭・роли`: язык (🇷🇺 Русский, 🇬🇧 English), уведомления (🔔 Releases, 📣 News), игры (Factorio, Minecraft, Rust, Valheim, CS2). Список разрешённых ролей зашит в `plan.go` (`SelfRoles`), тест проверяет, что тарифные и служебные роли туда не попадают.

## Бот
Приложение `Stokehold` (id в CLAUDE.md), приватное, помечено как бот, в описании сказано, что это бот. Приглашается с правами `2252900130712594`. Токен только в `.env` (локально) и `/etc/stokehold/bot.env` (сервер, права 0600).

Две части:
- `cmd/discord-setup` расставляет каналы, роли и закрепы. Идемпотентен, существующее не меняет.
- `cmd/stokehold-bot` (HTTP, без gateway): принимает нажатия кнопок на `https://api.stokehold.online/discord/interactions`. Проверяет подпись ed25519 и свежесть запроса (5 минут), выдаёт или снимает только роли из `SelfRoles`. Развёртывание: `deploy/stokehold-bot.service` (systemd, DynamicUser, ограничения) и `deploy/Caddyfile` (HTTPS).

## Блокировка Discord и обход
С российского VPS (stokehold.ru) `discord.com` и Telegram не открываются, GitHub и Google работают (проверено 2026-10-31). Входящие запросы от Discord к нашему адресу доходят, исходящие вызовы бота к Discord API нет. Решение: на VPS стоит клиент xray (VLESS+Reality) к VPN-серверу во Франкфурте, локальный SOCKS на 127.0.0.1:1080, и **только** сервис бота ходит через него (`deploy/examples/bot-proxy.conf`, `deploy/xray.service`). Остальной трафик и SSH идут напрямую. Проверено: кнопка выдаёт и снимает роль.

Примечания:
- На VPN-сервере создан клиент `stokehold-vps` в существующем inbound x-ui (перед правкой сделана копия базы `/etc/x-ui/x-ui.db.bak-pre-stokehold-*`). UUID клиента не хранится в репозитории: локально `~/.stokehold-secrets/`, на VPS `/etc/xray/config.json` (0640 root:xray).
- Другой сервер owner-host-3 достаёт Discord напрямую, но владелец запретил его трогать, он в схеме не используется.
- Для российских участников Discord по-прежнему доступен только через обход блокировок. Это риск единственной площадки сообщества, решение о которой принято владельцем.

## Запуск
```
discord-setup -invite-for <APP_ID>                           # ссылка приглашения бота
DISCORD_BOT_TOKEN=... discord-setup -guild <ID>              # расстановка (повторно безопасно)
DISCORD_BOT_TOKEN=... discord-setup -guild <ID> -remove-legacy -clean-defaults
```
`-remove-legacy` удаляет каналы и категории прежних раскладок из `Plan.Legacy`, `-clean-defaults` стандартные пустые каналы нового сервера. Остальное не трогают.

## Модерация
Правила в `📜・правила`, памятка модератора в `🛡・модераторы`. Автомодерацию Discord включает владелец (Настройки сервера → Модерация → AutoMod). Права Manage Server боту по умолчанию не выданы (нужно только для `-onboarding`).

## Модерация, магазин и журналы (2026-10-31)
Игровых ролей больше нет: остались язык и уведомления. Иерархия персонала (Founder, Curator, Moderator, Helper) и ветка магазина (Shop Curator, Shop Operator) описаны в docs/moderation.md и docs/shop-operations.md. Бот теперь умеет:
- slash-команды модерации `/warn /warnings /timeout /untimeout /kick /ban /unban /purge` (регистрация: `discord-setup -guild ID -register-commands APP_ID`);
- тикеты магазина: кнопка в `🛒・купить-лицензию`, приватный канал на клиента;
- копирование журнала аудита в `📜・события`.
Переменные сервиса бота: `DISCORD_APP_ID`, `DISCORD_GUILD_ID`, `STOKEHOLD_BOT_WARNS` (файл предупреждений) рядом с токеном и публичным ключом. Обновить тексты закрепов: `discord-setup -guild ID -repost`; убрать игровые роли: `-remove-legacy`.

## Сообщество и онбординг (2026-10-31)
Сервер включён как сервер сообщества: правила в `📜・правила`, обновления Discord в `🛡・модераторы`, у участников подтверждённая почта и фильтр медиа. Новичку при входе задаются три вопроса: язык (обязательный, одна роль), что присылать (релизы, новости) и как обращаться (Он, Она, Без обращения; можно пропустить). Роли обращения видят все участники, поэтому вопрос необязательный. Каналы по умолчанию: четыре публичные категории.

Включение сообщества требует Administrator, так что его делает владелец вручную. Вопросы можно создать и командой `discord-setup -guild ID -onboarding`, но боту для этого нужно право Manage Server; в этот раз они заведены через интерфейс. Роли обращения создаёт сам `discord-setup`.

## AutoMod
`discord-setup -guild ID -automod` создаёт правила, которых ещё нет: спам, массовые упоминания (от 6, таймаут 5 минут), мошеннические фразы про нитро (таймаут 10 минут). Срабатывания идут в `📋・журнал`, персонал в исключениях. Существующие правила не меняются, их можно править в Discord. Готовый словарь грубостей Discord для этого сервера не принял, поэтому мат в список добавляет владелец. Требование 2FA для модераторов включает только владелец сервера, и только после того, как включит 2FA на своём аккаунте. Роль Founder можно выдать командой `-founder USER_ID`.

## Подробные логи и жалобы
Категория `📜 ЛОГИ` (видят модераторы и выше): `💬・сообщения` (изменено: было и стало, автор, канал, ссылка; удалено: текст и вложения; массовое удаление), `👥・участники` (вход, выход с ролями, смена ролей, ника, имени, аватара), `🔊・голос` (вход, выход, перемещение), `🗄・сервер` (приглашения, ветки), `🛡・автомод` (сработавшие правила). Команды бота пишутся в `🤖・бот`, события из журнала аудита (баны, роли, каналы, вебхуки) в `📜・события`, наказания в `📋・журнал` как «Дело #N». Всё это embed'ами с цветом по типу события.

Для этого у бота теперь есть соединение с gateway Discord (до этого он работал только по HTTP). Нужны два привилегированных интента: **Server Members** и **Message Content** (Developer Portal → Bot → Privileged Gateway Intents). Без Message Content бот пишет, что текст недоступен. Без Server Members не будет входов, выходов и смены ролей. Бот сам отступает: если Discord отказал, интент отключается и это один раз пишется в журнал службы. Выключить gateway целиком: `STOKEHOLD_GATEWAY=off`. Старый текст сообщения бот помнит в памяти (последние 5000), после перезапуска первое изменение старого сообщения покажет «не было в памяти бота». Исходящий трафик gateway идёт через `HTTPS_PROXY`, как и остальное.

Жалобы: `/report user reason` у любого участника и пункт меню сообщения «Пожаловаться на сообщение». Жалоба приходит в `📣・жалобы` с пингом Moderator и кнопками «Взять в работу», «Предупредить», «Решено», «Отклонить». Кнопки жмут Helper и выше, «Предупредить» только Moderator и выше (предупреждение идёт тем же путём, что `/warn`, участнику уходит личное сообщение, если у него они открыты). Не больше 5 жалоб в час и не чаще раза в 30 секунд на человека, на себя и на ботов жаловаться нельзя. Состояние хранится в файле `STOKEHOLD_BOT_REPORTS`. Чтобы появились команды, повторно зарегистрируйте их: `discord-setup -guild ID -register-commands APP_ID` и запустите `discord-setup -guild ID` для новых каналов. Внимание: регистрация перезаписывает набор команд сервера целиком, поэтому команды панели (`-register-panel-commands`) нужно регистрировать после неё.

## Жалобы и апелляции: как они работают
**Жалобы.** Участник пишет `/report` или выбирает «Пожаловаться» в меню сообщения. Карточка приходит в `📣・жалобы` и пингует Moderator. Название канала осталось прежним: переименование в `discord-setup` создало бы второй канал рядом со старым. «Взять в работу» видят коллеги, поэтому одну жалобу дважды не разбирают. Срок указан в подписи карточки: взять в течение 24 часов, закрыть в течение 72. Каждые 10 минут бот проверяет открытые карточки: просроченная краснеет, в канал уходит один пинг на каждый уровень («не взята за 24 часа», «не закрыта за 72 часа»). «Предупредить» создаёт дело и отправляет участнику личное сообщение с номером дела, «Решено» значит «меры приняты другим способом», «Отклонить» открывает окно с обязательной причиной. Автор жалобы получает в личные сообщения короткий итог («рассмотрена, меры приняты» или «отклонена» с причиной); что именно сделали с нарушителем, ему не говорят. Если у автора закрыты личные сообщения, итог не доходит, это ничему не мешает.

Жалобы на сотрудника (любая роль персонала, включая магазин) идут в `🧭・кураторы`, видимый только Curator и Founder. Пинг получает Curator, кнопки у остальных не работают. Жалобу на ложную или повторную жалобу бот не обрабатывает: автору можно выдать предупреждение обычной командой `/warn`.

**Апелляции.** `/appeal case:<номер> text:<доводы>` подаёт сам наказанный в течение 14 дней. Обжаловать можно предупреждение, таймаут и исключение; номер дела бот присылает в личном сообщении в момент наказания и пишет его в `📋・журнал`. Блокировку обжалуют в личных сообщениях администрации: заблокированный не может использовать команды. По одному делу апелляция подаётся один раз, решение окончательное. Карточка приходит в `🧭・кураторы`. В плане нет роли «старший модератор», поэтому её роль выполняют Curator и Founder. Решить не может тот, кто выносил наказание (бот отвечает отказом, это видно только нажавшему). «Принять» отменяет наказание автоматически: предупреждение удаляется из списка, таймаут снимается, если ещё идёт, исключение отменить нельзя, оно записывается как отменённое. «Отклонить» требует причину. В обоих случаях запись попадает в `📋・журнал` как новое дело, а подавший получает в личные сообщения решение и пояснение. Целевой срок решения 72 часа, он написан в подписи карточки. Просрочку апелляций бот пока не отслеживает.

Переменные бота: `STOKEHOLD_BOT_REPORTS` (файл жалоб и счётчик дел), `STOKEHOLD_BOT_APPEALS` (файл дел и апелляций, без него всё хранится только в памяти). Чтобы заработали `/appeal` и новые каналы: `discord-setup -guild ID`, затем `discord-setup -guild ID -register-commands APP_ID` (и после неё `-register-panel-commands`, если используете команды панели), затем перезапуск `stokehold-bot`. Старые дела, вынесенные до обновления, подать на апелляцию нельзя: бот их не записывал.

## Канал установки
`🛠・установка` в категории «ИНФОРМАЦИЯ»: закреплённое сообщение с требованиями (Linux с systemd и OpenSSL 3, amd64 или arm64, для Windows и macOS VPS или WSL2), командами установки, первым входом, Caddy, обновлением и удалением. Текст лежит в `internal/discordsetup/texts_install.go`; обновить закреп: `discord-setup -guild ID -repost`. Тексты правил, устава и FAQ тоже обновлены под жалобы, апелляции и установку, чтобы `-repost` их подхватил.
